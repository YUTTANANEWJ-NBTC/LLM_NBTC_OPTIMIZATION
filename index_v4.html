ก่อนที่จะนำโมเดลไปผ่าแยกลงการ์ดจอหลายๆ ใบด้วย 4 แนวทาง เราจำเป็นต้องเข้าใจก่อนว่าใน **1 ชั้นเดี่ยวๆ (1 Layer)** ข้อมูล Token ไหลผ่านแผนกอะไรบ้าง และทำไมโมเดลถึงต้องคำนวณทีละชั้นเรียงตามแนวตั้งโดยข้ามขั้นไม่ได้

01

ขั้นที่ 1 (บนสุดของตึก): Input Tokens & Vector Embedding Tokenization

มิติเวกเตอร์ X ∈ ℝ^(Batch × Seq_Len × 5,120)

ผู้ใช้พิมพ์ประโยคคำถามเข้ามา เช่น "ฉัน ไป ซื้อ ชา เขียว" ระบบ Tokenizer จะแปลงคำแต่ละคำเป็นรหัสตัวเลข (Token IDs) จากนั้นวิ่งผ่านตาราง Embedding Table เพื่อแปลงเป็นเวกเตอร์ตัวเลขทศนิยมขนาด 5,120 มิติ (สำหรับ Qwen 27B) ซึ่งเวกเตอร์ชุดนี้คือตัวแทนความหมายเริ่มต้นของคำ และจะทำหน้าที่เป็นวัตถุดิบป้อนเข้าสู่ Layer ที่ 1 ทางด้านบนสุดของโมเดล

ตัวอย่างข้อมูล: ["ฉัน", "ไป", "ซื้อ", "ชา", "เขียว"] ➔ Token IDs [421, 882, 1204, ...] ➔ เวกเตอร์ขนาด (5 × 5,120)
02

ขั้นที่ 2: แผนกที่ 1 ของ Layer 1 — Grouped-Query Attention (GQA) 48 Q-Heads : 8 KV-Heads

ประหยัดแรม KV Cache 6 เท่า!

เวกเตอร์ขนาด 5,120 จะถูกส่งเข้าไปยังแผนก Attention เพื่อให้คำแต่ละคำ "สบตากันและมองหาความสัมพันธ์" (เช่น คำว่า "เขียว" มีความสัมพันธ์เชื่อมโยงกับ "ชา"):

1. แตกเป็น 48 หัว Q และ 8 หัว KV

เวกเตอร์จะถูกคูณเมทริกซ์ $W_Q, W_K, W_V$ แตกออกเป็น 48 หัวคำถาม (Query Heads) และ 8 หัวคำตอบ (KV Heads) โดยทุกๆ 6 หัว Q จะแชร์ใช้ 1 หัว KV ร่วมกัน (อัตราส่วน 6:1) เช่น Q1–Q6 คู่กับ KV1, Q7–Q12 คู่กับ KV2

2. Softmax ทำจบในแต่ละหัว 100%

แต่ละหัวจะคิดสมการ $\text{Softmax}(Q K^T / \sqrt{d_k}) V$ แยกขาดจากกันโดยสิ้นเชิง ไม่ต้องนำคะแนนข้ามหัวมาบวกรวมกันเลย! ทำให้หัว Attention แต่ละหัวเป็นอิสระต่อกัน 100% เหมาะอย่างยิ่งต่อการผ่าแยกลง GPU คนละใบ

3. รวมผล Concat + คูณ W_O + Residual

พอคิดเสร็จครบทั้ง 48 หัว จะนำเวกเตอร์มาต่อแถวเรียงกัน (Concat) แล้วคูณเมทริกซ์ $W_O$ เพื่อรวมผลกลับมาเป็นเวกเตอร์ขนาด 5,120 ช่องเท่าเดิม จากนั้นนำไปบวกกับเวกเตอร์ตั้งต้นผ่าน ทางลัด Residual Connection: $X_{\text{mid}} = X + \text{Attention}(X)$

03

ขั้นที่ 3: แผนกที่ 2 ของ Layer 1 — SwiGLU FFN (Feed-Forward Network) คลังความรู้แบบ Dense MLP

ขยายมิติ: 5,120 ➔ 18,944 ➔ 5,120

หลังจากคำแต่ละคำสบตากันแล้ว ข้อมูลเวกเตอร์ $X_{\text{mid}}$ จะถูกส่งมาที่แผนก Feed-Forward Network (FFN) ซึ่งทำหน้าที่เป็นเหมือน "สมองดึงคลังความรู้เชิงลึก" โดยมีขั้นตอนการคำนวณแบบ SwiGLU ดังนี้:

1. ขยายมิติขาขึ้น (Expand): เวกเตอร์ 5,120 ช่อง คูณเมทริกซ์ $W_{\text{gate}}$ และ $W_{\text{up}}$ ขยายเป็นกระดานดำ 18,944 ช่อง
2. ประตูเปิด-ปิด SwiGLU: ผลลัพธ์ = $\text{Swish}(X \cdot W_{\text{gate}}) \odot (X \cdot W_{\text{up}})$ เพื่อคัดกรองข้อมูลสำคัญ
3. ยุบมิติขาลง (Compress): คูณเมทริกซ์ $W_{\text{down}}$ บีบมิติจาก 18,944 ช่องกลับมาเป็น 5,120 ช่องเท่าเดิม

สุดท้ายนำผลลัพธ์บวกกลับเข้า Residual Connection รอบสอง จะได้เวกเตอร์ผลลัพธ์สมบูรณ์ของ Layer 1 เรียกว่า $X_{\text{Layer 1}}$!

04

ขั้นที่ 4: ส่งไม้ต่อจาก Layer 1 ลงสู่ Layer 2 ➔ Layer 3 ➔ ... ➔ Layer 64 Sequential Dependency

ต้องรอกันทีละชั้น ข้ามขั้นไม่ได้!

นี่คือเหตุผลที่ตึก Transformer ต้องเรียงตามแนวตั้ง! ค่าเวกเตอร์ $X_{\text{Layer 1}}$ ที่หลุดออกมาจากด้านล่างของ Layer 1 จะทำหน้าที่เป็นวัตถุดิบ (Input) วิ่งเข้าสู่หัวตึกของ Layer 2 ทันที จากนั้น Layer 2 จะนำเวกเตอร์นี้ไปคูณ $W_Q, W_K, W_V$ เป็น Query/Key/Value ชุดใหม่ของ Layer 2 และผ่าน Attention กับ FFN ซ้ำอีกรอบ และส่งต่อให้ Layer 3, 4, ... จนกระทั่งถึง Layer 64!

05

ขั้นที่ 5 (ล่างสุดของตึก): ปลายทางออกสู่ LM Head (Token Prediction) Vocabulary Softmax

พ่นคำถัดไปออกมา 1 คำ!

เมื่อเวกเตอร์ไหลทะลุผ่านครบทั้ง 64 ชั้นจนถึงชั้นล่างสุด จะถูกปรับสเกลด้วย RMSNorm สุดท้าย แล้วส่งเข้าสู่ LM Head (Un-embedding Matrix) เพื่อแปลงจากเวกเตอร์ 5,120 ช่อง ออกมาเป็นคะแนนความน่าจะเป็นของคำศัพท์ทั้ง 151,643 คำในพจนานุกรม และเลือกคำที่มีคะแนนสูงสุดพ่นออกมา (เช่น คำว่า "อร่อย")

แนวทางที่ 1 · LATENCY CHAMPION Strategy A: 12 Replicas × TP2

TP (Tensor Parallelism) — ผ่าซีกทุกชั้นตามแนวตั้ง ช่วยกันรุมคิดในชั้นเดียวกัน

ทั้ง GPU 1 และ GPU 2 มีตัวตนอยู่ในชั้นเดียวกัน รุมคำนวณและซิงค์ตัวเลขกันด้วย All-Reduce ไม่มีใครต้องนั่งรอใคร!

ขั้นตอนการไหลของข้อมูลจากบนลงล่างใน TP2 (Top-to-Bottom Execution Flow)

ก้าวที่ 1: Token เข้าสู่ GPU 1 และ GPU 2 พร้อมกัน Input Replicated

เมื่อ Token คำถามเข้ามา เวกเตอร์ $X$ จะถูกส่งเข้าไปในหน่วยความจำของทั้ง GPU 1 และ GPU 2 พร้อมกันเป๊ะ (ขนาด 5,120 มิติ)

ก้าวที่ 2: ผ่าครึ่ง 48 หัว Attention! (GQA Slicing) Column Parallel

แทนที่การ์ดใบเดียวจะต้องคิดทั้ง 48 หัว เราผ่าครึ่งแบ่งกันทันที:

GPU 1: รับผิดชอบ Q1–Q24 และคู่กับ KV1–KV4 (คิดเสร็จในตัว)
GPU 2: รับผิดชอบ Q25–Q48 และคู่กับ KV5–KV8 (คิดเสร็จในตัว)

*Softmax คำนวณจบในแต่ละการ์ด 100% จากนั้น GPU 1 คูณครึ่งซ้ายของ $W_O$ ได้ก้อน $A_1$ และ GPU 2 คูณครึ่งขวาของ $W_O$ ได้ก้อน $A_2$

⚡ ก้าวที่ 3: All-Reduce Sync ครั้งที่ 1 (เอาผลลัพธ์มา "บวกกันตรงๆ") Sum Reduction

ทำไมต้องเอาค่า $A_1 + A_2$ มา "บวกกัน" (ไม่ใช่หาค่าเฉลี่ย Average)? ตามกฎพีชคณิตเชิงเส้น:

ผลรวม Attention = [Head_1..24 | Head_25..48] · [W_O_บน / W_O_ล่าง] = (Head_1..24 · W_O_บน) + (Head_25..48 · W_O_ล่าง) = A_1 + A_2

หลังการ์ดทั้งสองบวกเลขเสร็จผ่าน NVLink/PCIe ทั้ง GPU 1 และ GPU 2 จะมีเวกเตอร์ผลรวมก้อนเดียวกันเป๊ะ ขนาด 5,120 ช่อง!

ก้าวที่ 4: ผ่ากระดานดำ FFN คนละครึ่ง (Column-Row Parallel Matrix Slicing) Column ➔ Row

กระดานดำ FFN ขนาด 18,944 ช่อง จะถูกผ่าคนละครึ่ง (คนละ 9,472 ช่อง):

💡 ตัวอย่างตัวเลขรูปธรรม (จำลองเมทริกซ์ 6×6 ผ่าครึ่งเป็น 6×3):
GPU 1 (ครึ่งแรก):
• คูณขาขึ้น $W_{\text{gate}}, W_{\text{up}}$ คอลัมน์ที่ 1..3
• เข้าสูตร SwiGLU ได้ผลลัพธ์ 3 ช่อง
• คูณขาลง $W_{\text{down}}$ แถวที่ 1..3 ได้เวกเตอร์ $Y_1$
GPU 2 (ครึ่งหลัง):
• คูณขาขึ้น $W_{\text{gate}}, W_{\text{up}}$ คอลัมน์ที่ 4..6
• เข้าสูตร SwiGLU ได้ผลลัพธ์ 3 ช่อง
• คูณขาลง $W_{\text{down}}$ แถวที่ 4..6 ได้เวกเตอร์ $Y_2$
⚡ ก้าวที่ 5: All-Reduce Sync ครั้งที่ 2 + ไหลลงสู่ Layer 2 ➔ 64 128 Syncs / Token

นำ $Y_1 + Y_2$ มารวมกันผ่าน All-Reduce ครั้งที่สอง จบ Layer 1 อย่างสมบูรณ์! จากนั้นเวกเตอร์จะไหลลงสู่หัวตึก Layer 2 และทำซ้ำแบบนี้ 64 ชั้น (รวม 128 ครั้ง All-Reduce ต่อ 1 Token)

TEP / EP (Tensor + Expert Parallelism) — ผ่า Attention แต่แจกผู้เชี่ยวชาญ MoE เต็มตัว

ผ่าหัว Attention ด้วย TP แต่ในส่วน FFN ที่มีหลายผู้เชี่ยวชาญ (MoE) ให้การ์ดแต่ละใบถือ Expert เต็มตัว ไม่ต้องผ่าเมทริกซ์ซอยย่อย!

ขั้นตอนการไหลของข้อมูลใน TEP (Top-to-Bottom MoE Routing)

ก้าวที่ 1–3: คำนวณ Attention แบบ TP8 + All-Reduce

ในส่วนของ Attention ทุกการ์ด (เช่น 8× B200) ช่วยกันผ่าหัว Attention เหมือน TP ปกติ แล้วรวมผลลัพธ์ด้วย All-Reduce

ก้าวที่ 4: MoE Router คัดเลือกผู้เชี่ยวชาญ 6 ตัว จาก 256 ตัว Top-6 Gating

แทนที่จะต้องรันกระดานดำ FFN ขนาดยักษ์ 284 พันล้านพารามิเตอร์ โมเดล MoE จะมี Router (หัวหน้าห้อง) คอยคำนวณคะแนนว่า สำหรับ Token คำนี้ ควรส่งไปให้ผู้เชี่ยวชาญเบอร์ไหน เช่น เลือก Expert #14, #42, #88, #102, #175, #210

ก้าวที่ 5: ส่ง Token ไปหาการ์ดที่ถือ Expert เต็มตัว (Intact Experts) 32 Experts / GPU

การ์ดแต่ละใบถือ Expert เต็มตัวใบละ 32 ตัว (8 GPUs × 32 = 256 Experts) เมื่อ Router บอกว่าต้องใช้ Expert #42 ข้อมูล Token ก็จะถูกส่งผ่าน NVLink ไปยัง GPU ใบที่ถือ Expert #42 นั้น โดยที่ Expert ตัวนั้นสามารถคำนวณแบบเต็มความเร็ว (Full Matmul) โดยไม่ต้องเสียเวลาผ่าซีกเมทริกซ์ให้เล็กลงจนสูญเสียความคุ้มค่าของการคำนวณบนการ์ดจอ!

ก้าวที่ 6: รวมผลลัพธ์จาก 6 ผู้เชี่ยวชาญ แล้วไหลลงสู่ Layer 2 .. 60

นำคำตอบจากทั้ง 6 Experts มาถ่วงน้ำหนักตามคะแนน Router แล้วรวมเป็นเวกเตอร์ก้อนเดียว ก่อนไหลลงสู่ Layer ถัดไป

🤔 ทำไม Qwen 3.8 27B ถึงใช้ TEP ไม่ได้?

เพราะ Qwen 3.8 27B เป็นโมเดลแบบ Dense Transformer 100% (พารามิเตอร์ 27B ตัว ทำงานพร้อมกันหมดทุกคำ ไม่มีแบ่งเป็น 256 Experts เหมือน DeepSeek) เมื่อไม่มี Expert ให้แจกจ่าย การพยายามใช้ Expert Parallelism จึงเป็นไปไม่ได้เลย ทางออกเดียวที่ดีที่สุดของโมเดล Dense จึงคือ TP (Tensor Parallelism) ร่วมกับ DP (Data Parallelism)!

แนวทางที่ 3 · ASSEMBLY LINE Vertical Floor Slicing (สายพานโรงงาน)

PP (Pipeline Parallelism) — แบ่งตึกคนละชั้น ต่อคิวเหมือนสายพานโรงงาน

GPU 1 ดูแลชั้น 1–32 (ครึ่งบนของตึก) ส่วน GPU 2 ดูแลชั้น 33–64 (ครึ่งล่างของตึก) ส่งมอบข้อมูลข้ามการ์ดแค่ครั้งเดียวที่รอยต่อชั้น!

ขั้นตอนการไหลของข้อมูลใน PP2 (Floor-by-Floor Execution)

ก้าวที่ 1: GPU 1 คำนวณ Layer 1 ถึง Layer 32 รวดเดียวในใบเดียว! 0 Syncs across GPUs

GPU 1 มีทั้ง 48 Q-Heads และ FFN เต็มก้อนของชั้น 1–32 อยู่ใน VRAM ของตัวเอง จึงคำนวณวนตั้งแต่ชั้น 1 ถึง 32 ได้ลื่นไหล 100% โดยไม่ต้องส่งสายไฟคุยกับ GPU 2 เลยแม้แต่ครั้งเดียว!

🚨 แต่จุดตายคือ: ระหว่างที่ GPU 1 กำลังคิดชั้น 1–32 อยู่นี้ GPU 2 จะต้อง "นั่งตบยุงว่างงาน (Idle Bubble)" รอไปเฉยๆ เพราะยังไม่มีข้อมูลไหลมาถึง!
⚡ ก้าวที่ 2: ส่งไม้ต่อข้ามการ์ดแค่ครั้งเดียวที่รอยต่อชั้น 32 ➔ 33! P2P Activation

เมื่อ GPU 1 คิดจบชั้น 32 จะส่งค่าเวกเตอร์ $X_{32}$ ก้อนเล็กๆ (ขนาดเพียง 5,120 floats) ข้ามสาย PCIe หรือสาย LAN ข้ามเครื่องไปยัง GPU 2 เพียงจังหวะเดียว!

ก้าวที่ 3: GPU 2 รับไม้ต่อ คำนวณ Layer 33 ถึง Layer 64 จนจบ Output Generation

GPU 2 คิดชั้น 33–64 รวดเดียวจนจบ แล้วพ่นคำตอบออกทาง LM Head! (และคราวนี้ ถ้าไม่มีผู้ใช้คนอื่นส่งคำถามตามมาติดๆ GPU 1 ก็จะกลายเป็นฝ่ายนั่งตบยุงว่างงานแทน!)

แนวทางที่ 4 · ENTERPRISE SCALE 24× A100/A40 vGPUs for 2,000 Users

DP / Whole Replicas & P/D Disaggregation — ตั้งตึกแยกหลายหลังคู่ขนาน

นำตึกที่เราสร้างจาก TP/PP มาวางขนานกันหลายๆ หลังเพื่อรับผู้ใช้พร้อมกัน 2,000 คน (30 Concurrent Requests)

4A Whole Replicas (12 ตึกคู่ขนาน × TP2)

🏆 ชนะเลิศเรื่องความเรียบง่าย

จัดเรียงการ์ดจอทั้ง 24 ใบ ออกเป็น 12 ตึกอิสระ (ตึกละ 2 การ์ดจอ: ตึก 1 = vGPU 1–2, ตึก 2 = vGPU 3–4 ... ตึก 12 = vGPU 23–24):

1. Ray Serve Prefix-Aware Router ด้านบนสุด:

คอยทำหน้าที่เป็นพยาบาลคัดกรอง แจกผู้ใช้ 30 คนลงไปที่ตึกทั้ง 12 หลังอย่างสม่ำเสมอ ทำให้แต่ละตึกรับภาระเพียง ~2.5 คนพร้อมกัน

2. การสื่อสารข้ามตึกเป็นศูนย์ (0% Cross-Node Overhead):

แต่ละตึกมีโมเดลครบ 64 ชั้นสมบูรณ์ ทำงานเสร็จในตัวเอง ไม่ต้องส่งสายไฟคุยข้ามตึกเลยแม้แต่ไบต์เดียว! ความเร็ว Throughput จึงทวีคูณตามจำนวนตึก 12 เท่าตรงๆ

4B P/D Disaggregation (แยกตึกอ่านโจทย์ ออกจากตึกเขียนคำตอบ)

🚀 เหมาะกับงาน RAG เอกสารหนา

แบ่งการ์ดจอ 24 ใบออกเป็น 2 แผนกเฉพาะทาง:

1. ตึก Prefill Pool (8 vGPUs แบบ TP4):

รับเอกสารคำถามยาวๆ 8,000–32,000 tokens มาอ่านรวดเดียวพร้อมกัน (Compute-Bound) เพื่อสร้างก้อน KV Cache ครบทั้ง 64 ชั้น

2. สะพานส่งมอบ KV Cache ผ่าน NIXL:

โยนก้อนหน่วยความจำ KV Cache ข้ามสาย InfiniBand/PCIe ไปให้ตึก Decode

3. ตึก Decode Pool (16 vGPUs แบบ TP2):

รับไม้ต่อมาพ่นคำตอบทีละคำ (Memory-Bandwidth Bound) ทำให้รอบการเขียนคำตอบไม่ถูกรบกวนจากการอ่านเอกสารหนักๆ
